## PostgreSQL Data Types

- `SMALLINT`: 2 bytes.
- `INTEGER` / `INT`: 4 bytes; good for money (in cents) or IDs.
- `BIGINT`: 8 bytes.
- `NUMERIC(p, s)` / `DECIMAL`: good for money.
- `REAL`: 4 bytes; do NOT use for money.
- `DOUBLE PRECISION`: 8 bytes; do NOT use for money.
- `TEXT`: – variable length strings; postgres secret sauce.
- `VARCHAR(255)`: variable length strings.
- `CHAR(n)`: fixed-length, space-padded.
- `BOOLEAN`.
- `DATE`: calendar date.
- `TIME`: time of day.
- `TIMESTAMP`: date + time.
- `TIMESTAMPZ`: date + time + timezone (UTC).
- `NULL`: is NOT false; it’s unknown.
- `UUID`: universally unique IDs.
- `JSON`: raw JSON text.
- `JSONB`: binary JSON, very fast access speeds.
- `ARRAY`.
- `TEXT[]`.
- `INT[]`.
- `ENUM`.

| Type          | Size | Auto-Increment | Index Speed | Good for Distributed? |
| :------------ | :--- | :------------- | :---------- | :-------------------- |
| **SERIAL**    | 4B   | Yes            | Very fast   | No                    |
| **BIGSERIAL** | 8B   | Yes            | Very fast   | No                    |
| **INTEGER**   | 4B   | Optional       | Very fast   | No                    |
| **UUID**      | 16B  | Optional       | Slower      | Yes                   |

- Since Postgres 10, we have SQL standard IDENTITY (replaces SERIAL)

```sql
-- Timestamped UUID
id UUID PRIMARY KEY DEFAULT uuidv7()
```

## Custom Data Types, ENUM, & Regex

- `CREATE DOMAIN` creates a restricted alias for an existing base type by adding constraints (like `NOT NULL` or `CHECK`).
- `CREATE TYPE` creates a completely new, composite data type consisting of multiple named fields (similar to a struct or object).

```sql
-- Types
CREATE TYPE mood AS ENUM('sad', 'ok', 'happy');
CREATE TYPE address AS (
    street       TEXT,
    city         TEXT,
    state        CHAR(2),
    postal_code  TEXT,
    country      TEXT
);

CREATE TABLE user (
    address street_address
);

-- You need parentheses for SELECT and WHERE
SELECT (address).city FROM customers;

-- Domains
CREATE DOMAIN email_address AS TEXT
CHECK (VALUE ~* 'REGEX EXPRESSION HERE')

/*
    ~   regex case sensitive
    ~*  regex case insensitive
    !~  regex does not match case sensitive
    !~* regex does not match case insensitive
*/
```

```sql
CREATE TABLE IF NOT EXISTS users (
    user_id UUID PRIMARY KEY,
    email TEXT NOT NULL UNIQUE,
    age INT CHECK (age >= 18),
    created_at TIMESTAMP DEFAULT NOW(),
    banned BOOLEAN,
    last_login TIMESTAMP,
    address_id INT NOT NULL REFERENCES addresses(address_id)
);

ALTER TABLE users
ADD COLUMN is_active BOOLEAN DEFAULT true;

ALTER TABLE users
ALTER COLUMN email SET NOT NULL;

-- Need to drop and then create a new constraint. You don’t technically ever edit one.
ALTER TABLE users
DROP CONSTRAINT users_age_check,
ADD CONSTRAINT users_age_check CHECK (age >= 21);
```

## Interval

- `INTERVAL` supports: year, month, day, hour, minute, seconds, milliseconds, microseconds.
- You can do arithmetic against it, or generate from functions:
  - `INTERVAL '1 hour 10 minutes' / 2`
  - `INTERVAL '3 days 22 hours 1 minute' * 3`.

```sql
DELETE FROM users
WHERE last_login < NOW() - INTERVAL '2 years';
```

## Returning

- In PostgreSQL, the `RETURNING` clause allows you to return values from rows that were modified by `INSERT`, `UPDATE`, or `DELETE` statements and eliminates the need to execute a separate `SELECT` query right after a data modification.

```sql
-- Returns the newly generated 'id' and 'created_at' values
INSERT INTO users (name, email)
VALUES ('Alice', 'alice@example.com')
RETURNING id, created_at;
```

## Upsert

- **Upsert**: combines "update" and "insert" into a single, atomic command. If a row already exists based on a specified identifier (usually a primary key or unique index), the database updates it with new information. If the row does not exist, the database inserts a new row.
  -- In PostgreSQL, `EXCLUDED` is a special table alias used within an `ON CONFLICT ... DO UPDATE` clause. It references the row that was proposed for insertion (the values in your `VALUES` clause or `SELECT` statement) that failed to insert due to a conflict.

```sql
INSERT INTO users (email, name)
VALUES ('d@example.com', 'Alice')
ON CONFLICT (email)
DO UPDATE SET name = EXCLUDED.name
RETURNING *;
```

## Wildcards

### Case Sensitive Wildcards

- `WHERE email LIKE '%@gmail.com'`: zero or more characters.
- `WHERE email LIKE '_'`: exactly one character.
- `WHERE email ~ 'REGEX EXPRESSION HERE'`.

### Case Insensitive Wildcards

- `WHERE email ILIKE '%@gmail.com'`: zero or more characters.
- `WHERE email ILIKE '_'`: exactly one character.
- `WHERE email ~* 'REGEX EXPRESSION HERE'`.

## Aggregate Functions

- Used with `GROUP BY` clause:
  - `MIN`, `MAX`, `AVG`, `COUNT`, `SUM`.

## Scalar Functions

- Scalar functions differ from aggregate functions because they operate on each individual row.
- String/text:
  - `UPPER()`.
  - `LOWER()`.
  - `LENGTH()`.
  - `TRIM()`.
  - `SUBSTRING(str, start_index, length)`.
  - `CONCAT(str1, str2)`.
  - `REPLACE(str, from, to)`.
- Date/time:
  - `NOW()`.
  - Standard SQL defines special functions like `CURRENT_DATE`, `CURRENT_TIME`, `CURRENT_TIMESTAMP`, and `USER` without parentheses. PostgreSQL implements them to conform with the ANSI/ISO SQL standard.
  - `AGE(timestamp1, timestamp2)`: difference between to timestamps.
  - Extractions:
    - `SELECT EXTRACT(MONTH from NOW());`.
    - `WHERE EXTRACT(year FROM start_date) = 2025`.

## Functions

- Predefined operations we can call and reuse:
  - Can perform queries, do DML, perform arithmetic.
  - Functions MUST return a value (even if its just void).
  - Functions CANNOT perform TCL.
- Must be invoked as part of a query expression using `SELECT`.
- Best for one-time calculations, or one-off logic.

```sql
CREATE OR REPLACE FUNCTION add_numbers(a INT, b INT)
RETURNS INT AS $$
BEGIN
    RETURN a + b;
END;
$$ LANGUAGE plpgsql;

SELECT add_numbers(5, 15);

CREATE OR REPLACE FUNCTION add_user(p_email TEXT, p_age INT)
RETURNS VOID AS $$
BEGIN
    INSERT INTO my_schema.users(user_id, email, age) VALUES
    (gen_random_uuid(), p_email, p_age);
END;
$$ LANGUAGE plpgsql;
```

## Stored Procedures

- Another way to create predefined and reusable blocks of SQL commands and logic.
- Differ from functions because returns are optional and they CAN use TCL.
- Must be invoked as part of a query expression using `CALL`.
- Best for long running transactions, batch operations, etc.

```sql
CREATE PROCEDURE deactivate_user(p_user_id UUID)
LANGUAGE plpgsql
AS $$
BEGIN
    IF EXISTS (SELECT 1 FROM my_schema.users WHERE user_id = p_user_id)
    THEN
        UPDATE my_schema.users SET is_active = False
        WHERE user_id = p_user_id;
    ELSE
        RAISE NOTICE 'User % not found', p_user_id;
    END IF;
END;
$$;

CREATE PROCEDURE get_user_count(OUT total INT)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT COUNT(*) INTO total FROM my_schema.users;
END;
$$;

CALL get_user_count(NULL);

CREATE PROCEDURE get_invoice_sum_by_country(country TEXT, OUT total_sum NUMERIC)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT SUM(total) INTO total_sum FROM invoice
    WHERE billing_country = country
    GROUP BY billing_country;
END;
$$;

CALL get_invoice_sum_by_country('USA', NULL);

```
