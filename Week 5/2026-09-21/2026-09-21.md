## MongoDB

```bash
docker run -d --name mongodb-sandbox -p 27017:27017 -e MONGO_INITDB_ROOT_USERNAME=admin -e MONGO_INITDB_ROOT_PASSWORD=password mongo:8
```

- **MongoDB**: open-source NoSQL database designed to store data in flexible, JSON-like documents rather than traditional rows and tables. This architecture makes it highly scalable, fast, and adaptable for modern applications handling unstructured or rapidly evolving data.
- Constructs:
  - **Database**: A physical container for collections. Each database occupies its own set of files on the file system, and a single MongoDB instance can host multiple independent databases.
  - **Collection**: A grouping of MongoDB documents. Collections are analogous to tables in relational databases. However, unlike tables, collections do not enforce a rigid schema, meaning documents within the same collection can have entirely different structures.
  - **Document**: The basic unit of data in MongoDB, consisting of field-value pairs. Documents are stored in BSON (Binary JSON) format and are equivalent to rows in relational databases. They can easily represent complex hierarchical relationships using embedded sub-documents and arrays.
  - **Field**: A key-value pair within a document. A field name is a string, and its value can range from standard data types (strings, numbers, booleans) to arrays or nested documents. Fields are equivalent to columns.
  - **\_id (field)**: A mandatory unique identifier required for every document in a collection. It functions as the primary key and defaults to a **12-byte ObjectId** if no custom ID is provided during creation.

## MongoDB Schema

- Because MongoDB is schemaless, your application code manages the data structure, offering incredible flexibility when your application requirements change over time.
  - This means that fields can be added dynamically (with the option to create defined, enforced schemas if needed).
  - By default, MongoDB operates on a dynamic schema (often called schemaless). You do not need to alter a table definition or pre-define columns before inserting data.
  - Here is how MongoDB handles your data and subsequent CRUD operations when fields change:
    - **During insertion**: if you insert a document with a brand-new field, MongoDB accepts it immediately without complaints.
    - **During reads** (queries): if you run a query looking for a field that doesn't exist in a particular document, MongoDB won't crash or throw an error. It simply ignores that document or treats the missing field as null or undefined.
    - **During updates**: you can add new fields to existing documents on the fly using update operators like `$set`, or remove them using `$unset`.
- We can either enforce validation while creating a collection, or add validation after the collection already exists:
  - `additonalProperties` + `validationAction`: work in tandem to enforce the schema.
