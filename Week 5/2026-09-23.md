## JavaScript (JS)

- **JavaScript**: a high-level, interpreted programming language primarily used to make web pages interactive and dynamic.
  - Runs directly in the browser.
  - Allows developers to manipulate content, respond to user actions, control multimedia, and communicate with servers.
  - Case sensitive.
  - **Loosely typed**: we don’t declare the type of variable.
  - **Dynamically typed**: the type of variables are determined at runtime.

## Variables

- **Variable**: a container for storing data values, such as numbers, text, objects or more.
  - Variables let us label and reuse data within our application.
  - `let`: declares a variable that can be reassigned (block scope).
  - `const`: declares a variable that cannot be reassigned (block scope).
  - `var`: old way of declaring variables (global or function scope).

## Primitive Data Types

- **Primitive data type**: these data types comprising simple and single values, are held in memory.
  - `String`.
  - `Boolean`.
  - `Number`: integers and decimals.
  - `Null`: intentional empty value.
  - `Undefined`: variables that are declared but never assigned a value.
  - `Symbol`: unique identifier.
  - `BigInt`: for very large integers beyond `Number`'s limit (a number followed by an `n`).

## Hoisting

- **Hoisting** is a behavior in which variables and function declarations are moved (hoisted) to the top of their containing scope during compilation, before the code is executed.
- This means that we can sometimes use functions or variables before they are declared.
- `var` is hoisted, but initialized to `undefined`.
- `let`/`const` are hoisted but not initialized.
- For function expressions & arrow functions, only the variable is hoisted, not the function definition.

## Strict Mode

- Strict mode is a way to opt in to a stricter set of rules that help us write cleaner and safer code.
- It intentionally changes normal JS semantics, turning silent errors into thrown exceptions and allowing engines to better optimize code.
- Can be used at the top of a JS file or at the top of a function to only apply to a single function.
- Main benefits:
  - Catch bugs early: stops you from accidentally mistyping variable names and polluting the global scope.
  - Improves performance: eliminating highly dynamic features (like `with`) allows modern JavaScript engines to compile and optimize your code much faster.
  - Secures your Code: prevents `this` from accidentally leaking the global object, protecting system-level variables from unintended modifications.

| Feature              | Sloppy Mode (Default)                                              | Strict Mode ("use strict")                                             |
| :------------------- | :----------------------------------------------------------------- | :--------------------------------------------------------------------- |
| Undeclared Variables | Automatically creates a global variable.                           | Throws a `ReferenceError` .                                            |
| The `this` Keyword   | Defaults to the global object (`window` or `global`) if undefined. | Remains `undefined` in global function calls.                          |
| Duplicate Parameters | Allowed; the last parameter overwrites previous ones.              | Throws a `SyntaxError` (e.g., function `sum(a, a)` ).                  |
| Read-Only Properties | Silently fails when trying to write to non-writable objects.       | Throws a `TypeError` .                                                 |
| The `with` Statement | Allowed (but discouraged).                                         | Completely banned; throws a `SyntaxError` .                            |
| `eval` Scope         | Introduces new variables into the surrounding scope.               | Runs in its own sandbox scope; cannot create variables outside itself. |

## Modules

- A JavaScript **module** is a JavaScript file that can be imported into another JavaScript file.
- Allows developer to organize code into separate, reusable pieces instead of writing everything in a single script.
- Each module has its own scope (variables/functions inside are not automatically global).
- Prevents naming conflicts between different parts of code.
- Has default and named exports.
- Strict mode is enabled by default.
- Need to apply `type="module"` when importing into HTML.

## Events

- Events are actions that happen in the browser, usually because of human action like:
  - **UI**: `load`, `resize`, `scroll`.
  - **Mouse**: `click`, `dblclick`, `mouseover`, `mousemove`.
  - **Keyboard**: `keydown`, `keyup`, `keypress`.
  - **Form**: `submit`, `change`, `focus`, `blur`.
  - **Clipboard**: `copy`, `paste`, `cut`.
- Event listeners wait for events and execute a function when they occur.
  - When an event occurs, an event object is automatically passed to the event handler.
  - The event object contains:
    - Type of event.
    - The element that triggered it.
    - Mouse position.
    - Key pressed
    - Etc.
- Inline event handlers are possible, but not recommended (it's more maintainable to keep everything in a JS file).

## Event Propagation

- When an event occurs, it goes through 3 phases:
  - **Capturing phase**: the event starts at the root of the DOM (document) and traverses down to the element that triggered the event.
  - **Target phase**: at the element that triggered the event.
  - **Bubbling phase**: the event moves back up the DOM towards the root.
- Event listeners operate during the bubbling phase by default.
- `.preventDefault()`: prevents the default action (like following a link or submitting a form).
- `.stopPropagation()`: prevents the event from moving to other elements (up or down the DOM tree).
- `.stopImmediatePropagation()`: stops propagation and also stops any other handlers attached to the same element from running.

## Event Loop

- JavaScript is single-threaded, meaning it can only execute one task at a time.
- The **event loop** is the mechanism that allows JavaScript to perform non-blocking asynchronous operations (like fetching data, timers, or reading files) despite being single-threaded.

#### Core Event Loop Components

1. **Call Stack:**
   - A LIFO (Last-In, First-Out) data structure where your code's execution context is tracked.
   - Synchronous functions are pushed onto the stack and popped off once completed.

2. **Web APIs / Node.js APIs:**
   - Browser-provided environments (or Node.js equivalents) where asynchronous operations (like `setTimeout`, fetch requests, or DOM events) run outside the main thread so they don't block code execution.

3. **Task Queues (Callback Queues):**
   - **Microtask Queue:** Holds high-priority callbacks like Promises (`.then()`, `async/await`) and `queueMicrotask`.
   - **Macrotask Queue (Callback Queue):** Holds lower-priority callbacks like `setTimeout`, `setInterval`, and I/O operations.

#### How the Event Loop Works

1. **Execute Synchronous Code:** The engine executes everything currently on the Call Stack.
2. **Process Microtasks:** When the Call Stack is empty, the event loop immediately checks the **Microtask Queue** and executes all tasks inside it until the queue is completely empty.
3. **Process Macrotasks:** Next, the event loop takes a single task from the **Macrotask Queue** and pushes it onto the Call Stack for execution.
4. **Repeat:** The loop continuously repeats this cycle (stack empty → all microtasks → one macrotask → repeat).

## Async/Await & Promises

- `async`/`await`: modern syntax for working with asynchronous code in a way that looks and behaves more like synchronous code.
  - Syntactical sugar.
- A **Promise** is an object that represents the eventual result of an asynchronous operation.
  - These allow us to handle success and failures of these operations in a cleaner way.
  - Promises may be pending, fulfilled, or rejected.
