## Spring

- **Spring** is a Java framework used to build applications, especially web applications, APIs, and enterprise applications.
- Spring helps manage the complexity of a large Java applications by providing features such as:
  - **Dependency Injection** (DI): creates and manages objects for you instead of you manually creating them everywhere
  - **Inversion of Control** (IoC): framework controls how application components are created and connected.
  - **Web development**: Spring MVC can be used to build REST APIs and web applications.
  - **Database access**: integrates with technologies such as JPA, Hibernate, and JDBC.
  - **Spring Security**: provides authentication & authorization.
  - **Transaction management**: manage database transactions.
  - **Modular architecture**: you can use only the Spring modules your application needs.

## Dependency Injection (DI)

- Without DI, we would likely make concretions ourselves, and need to carefully manage them.
- With DI, we can define annotations, and then have objects initialized only when needed.

```java
@Service
public class UserService {}

@RestController
public class UserController {
    private final UserService service;
    public UserController(UserService service) {
        this.service = service;
    }
}
```

## Spring vs Spring Boot

- Both are Java frameworks, but Spring can be very difficult to setup on its own.
- Spring Boot is a framework built on top of Spring that makes it much easier and faster to create Spring applications.
- Spring Boot provides automatic convention over configuration, embedded servers, and convenient project setup.

| Spring                                  | Spring Boot                                 |
| :-------------------------------------- | :------------------------------------------ |
| The underlying ecosystem/framework      | Built on top of Spring                      |
| More configuration may be required      | Provides automatic configuration            |
| You often configure components yourself | Many things are configured automatically    |
| Can require external server setup       | Usually includes an embedded server         |
| More flexible/configurable              | Optimized for quickly building applications |
| Foundation                              | Simplified way to use Spring                |

## Spring Initializr (`https://start.spring.io`)

- **Spring Initializr is** a web-based tool from the Spring ecosystem that helps you quickly create the basic structure of a Spring Boot application.
- It generates a ready-to-use project with:
  - Project structure and configuration files.
  - Build tool setup (Maven or Gradle).
  - Java version selection.
  - Spring Boot dependencies (such as Spring Web, Spring Data JPA, Spring Security).
  - Basic application entry point.

## Spring Tools Suite (`https://spring.io/tools`)

- STS is traditionally an IDE based on Eclipse that makes Spring configuration easier.
- STS now support VS Code, Cursor, and more.

## Creating a Spring Boot App

- Install extensions in VS Code.
- Open command palette (`⌘⇧P`).
- Select `Spring Initializr: Create a Maven Project...`.
- Run the project on the CLI: `mvn spring-boot:run`.
- It should open up on `http://localhost:8080/` by default.

```java
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class MyRestController {
    @GetMapping("/")
    public String sayHello() {
        return "Hello World!";
    }
}
```

## Maven Wrapper Files

- Wrapper files: `mvnw` or `mvnw.cmd`.
- These allows us to run maven commands against our project:
  - Even if we don't have the correct version of Maven installed.
  - Or if we don't have it installed at all!
- For example:
  - We could run: `mvnw spring-boot:run`.
  - Instead of: `mvn spring-boot:run`.

## Spring Boot Properties

- Path: `src/main/resources/application.properties`.
- Built-in properties: `https://docs.spring.io/spring-boot/appendix/application-properties/index.html`.
- You could also add custom properties.

#### Inside `application.properties`:

```
custom.setting=No Quotes Needed
```

#### Inside Java:

```java
@RestController
public class MyController {
    @Value("${custom.setting}")
    private String customSetting;
}
```

## Static Content

- By default, Spring Boot will load static content from: `src/main/resources/static`.
- Put HTML, CSS, JS, images, etc here.

## Web App Standard Location

- **Warning**: do not use the `src/main/webapp` directory if your application is packaged as a JAR.
- Although this is a standard Maven directory, it works only with WAR packaging.

## Template Engines

- **Template engines** return views (markup) from server-side, instead of JSON responses.
- By default, Spring Boot will load templates in `src/main/resources/templates`.
- Spring Boot includes auto-config for the following template engines:
  - FreeMarker.
  - ThymeLeaf.
  - Mustache.

## Common Spring Boot Starters

- A **Spring Boot Starter** is a pre-configured dependency package that bundles together all the related libraries, automatic configurations, and properties needed to quickly enable a specific feature or technology (like web, security, or data) with a single dependency declaration.
- **`spring-boot-starter-web`**: Includes everything needed to build a web application, including an embedded Tomcat or Jetty server, Spring MVC, and other web-related dependencies.
- **`spring-boot-starter-data-jpa`**: Provides support for using Spring Data JPA for database access, including Hibernate as the default JPA implementation.
- **`spring-boot-starter-security`**: Offers Spring Security configurations for securing applications, including authentication, authorization, and common security features.
- **`spring-boot-starter-test`**: Includes dependencies and configurations for writing tests in a Spring Boot application, such as JUnit, Mockito, and Spring Test.
- **More starters**: `https://docs.spring.io/spring-boot/reference/using/build-systems.html#using.build-systems.starters`.

## Spring Boot Starter Parent

- Spring Boot provides a starter parent.
- This is a special starter that provides default configurations.
- Included in `pom.xml` when using Spring Initializr.
- Simply set the version of the `<parent>`, and all `<dependencies>` will be automatically versioned to ensure compatibility.
  - No need to individually list versions.
  - The Maven plugin is the same.
  - Configurations for dependencies and plugins will come from the parent!

```xml
<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>4.1.1</version>
  <relativePath/> <!-- lookup parent from repository -->
</parent>
```

## Spring Boot Actuator (`spring-boot-starter-actuator`)

- Exposes endpoints to monitor the health of our application, as well as return other metrics/info.
- We simply need to add the dependency to our POM file without needing to write additional code.
- REST endpoints are then automatically added to our application.
- We can secure these endpoints later with Spring Security.
- All endpoints will fall under `actuator`.
- By default, only `/health` is exposed.
- Configure inside `application.properties`.
  - Properties starting with `info` will be used in `/info`.
- We can also expose all endpoints with:
  - `management.endpoints.web.exposure.include=*`.

```
management.endpoints.web.exposure.include=*
management.endpoints.web.exposure.exclude=health,info
management.info.env.enabled=true

info.app.name=demo
info.app.description=Hello World!
info.app.version=1.0.0
```

| Endpoint       | Description                                                                       |
| :------------- | :-------------------------------------------------------------------------------- |
| `/health`      | Check app status; normally used by monitoring apps to see if your app is running  |
| `/info`        | Get information about your app (from `application.properties`)                    |
| `/auditevents` | Audit events for your application                                                 |
| `/beans`       | List of all beans registered in the Spring application context                    |
| `/mappings`    | List of all `@RequestMapping` paths                                               |
| Others         | `https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#page-title` |

## Spring Security (`spring-boot-starter-security`)

- Whenever you access `/actuator/beans`, Spring Security will prompt for login.
  - Default user name: `user`.
  - Default password: found in console when running the app (`Using generated security password`).
- Override default username and generated password in `application.properties`:
  - `spring.security.user.name=root`.
  - `spring.security.user.password=alpine`.

## Spring Logging

- `spring-boot-starter-webmvc` already contains the logging dependencies.
- We can set properties in our `application.properties` file to customize logging for Spring apps.
- **`%i`** is an integer index counter (starting at 0 or 1).
  - If a single day's log file exceeds the maximum size limit before the day ends, Logback creates a new file for the same day, incrementing this index (e.g., `app.2026-09-28.1.log.gz`, `app.2026-09-28.2.log.gz`).

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class MyFirstController {
  private static final Logger logger = LoggerFactory.getLogger(MyFirstController.class);
}
```

```properties
logging.file.name=logs/app.log
logging.level.io.github.tthn0.demo.rest=DEBUG
logging.logback.rollingpolicy.file-name-pattern=logs/app.%d{yyyy-MM-dd}.%i.log.gz
logging.logback.rollingpolicy.max-file-size=10MB
logging.logback.rollingpolicy.max-history=7
```
