## AWS Services

- **S3** (Simple Storage Service): cloud storage used to store and retrieve files, images, videos, backups, and other data.
  - An object storage service built to store master copies of your files.
- **CloudFront**: CDN that delivers websites, images, videos, and other content to users quickly by using servers located around the world.
  - Built to distribute those files globally with low latency.
- **Aurora & RDS** (Relational Database Service): database services used to store, organize, and manage structured data.
  - RDS supports database engines such as MySQL and PostgreSQL, while Aurora is an AWS-built relational database compatible with MySQL and PostgreSQL.
- **ECR** (Elastic Container Registry): managed container image registry used to store, manage, and retrieve Docker and other OCI container images.
  - **OCI** (Open Container Initiative): an organization that creates open standards for container technology, helping ensure that container images and runtimes work consistently across different platforms and tools, such as Docker and AWS.
- **ECS** (Elastic Container Service): a container orchestration service that runs, manages, and scales containerized applications without requiring you to manage the orchestration infrastructure yourself.
- **Route 53**: AWS's (DNS) service that translates domain names into IP addresses and routes users to websites and applications.

## ECS

- **Express mode**: makes AWS setup a load balancer and many other pieces of infrastructure for us.
- **Task execution role**: determines what services our container can do on our behalf.

## CloudFront

- **Origin**: tells CloudFront where to fetch content from when it needs to forward a request.
  - Our frontend and backend are separate services, so CloudFront needs to know about both.
- **Frontend origin**: An S3 bucket containing your front-end build files.
- **API origin**: our Application Load Balancer (ALB), which sits in front of our Java app and routes requests to our backend.
- On the distribution, setup 2 origins:
  - `java-api-origin`: this domain will point to the ALB SSL/TLS certificate location (due to HTTPS:443 listener rules – this is admittedly hacky and maybe a better way to do this).
  - `site`: this domain will point to our S3 bucket that stores our build artifacts from the front-end app.
- **Behaviors** describe what paths will be redirected to use our origins.
- Notice for all `/api/*` requests, we are NOT sending along the host header as we are connecting to the SSL/TSL cert endpoint directly (it is already set as the host via our origin; again this is hacky and probably a better way to do this).
- With the default behavior, we should create a CloudFront function so if a user tries to navigate to a view directly, they are consistently served the root of the SPA app instead `index.html` (not doing this will causes page refreshes to 404, as it will try and get something from the S3 bucket with an invalid location).
